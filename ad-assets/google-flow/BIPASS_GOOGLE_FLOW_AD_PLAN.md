# Bipass AI — cinematic Google Flow flythrough

## The concept

This is a 32-second continuous camera journey, split into four 8-second Flow generations. It is not a screen recording and not a sequence of flat UI cards.

The camera enters through the negative space of the Bipass **B**, discovers the interface as a huge spatial landscape, races through a rewriting tunnel made from words and coloured changes, follows a reviewed draft through the Auto Typer extension, then rides beside the typing caret inside Google Docs. Finally, every product layer collapses back into the Bipass logo.

The feeling is fast, precise, intelligent, and expensive. Motion carries momentum from one object into the next. Every transition has a physical cause; nothing merely fades because the next scene is needed.

## Format and Flow workflow

- Exactly four clips, each 8 seconds.
- 9:16 vertical, 1080×1920 or the highest available output quality.
- Use the best current Veo 3.1 model in Flow that gives strong image-to-video motion and supports your selected frames.
- Begin with **Frames to Video** using the pair specified for each clip.
- If a first-and-last-frame generation becomes too restrained, use only the first frame, attach the destination image as a visual ingredient, and tell Flow to land on that composition. Save the strongest final frame and use it as the next clip’s start frame.
- Generate four versions of each clip. Select for camera movement first, text stability second, then rerun the strongest prompt if needed.

Frame pairs:

1. `flythrough-keyframe-01-logo-portal.png` → `flythrough-keyframe-02-level-flyover.png`
2. `flythrough-keyframe-02-level-flyover.png` → `flythrough-keyframe-03-upload-portal.png`
3. `flythrough-keyframe-03-upload-portal.png` → `flythrough-keyframe-04-caret-chase.png`
4. `flythrough-keyframe-04-caret-chase.png` → `flythrough-keyframe-05-brand-payoff-clean.png`

## Spatial motion rules

- Interface screens are thin, rigid, matte UI planes suspended in a limitless warm-white studio—not rubber cards and not holograms.
- The camera may fly above, beside, between, and through these planes. At the first three seams it must match the supplied dynamic perspective and preserve a slight forward drift; only the final brand frame becomes front-facing.
- Use a cinematic 24–28mm virtual lens during flythroughs and a calmer 45–50mm feeling only for the final brand landing.
- Maximum camera roll is about 8 degrees. Use controlled banks, never dizzy spinning.
- Use strong speed ramps: a calm 0.4-second setup, rapid acceleration, a close flyby, then a confident deceleration into the feature landing.
- Preserve velocity across transitions. When the camera dives into a button or word, it must emerge from the same trajectory on the other side.
- UI planes never wobble, melt, stretch, or become soft. Text stays attached to its plane.
- Motion blur is allowed only during the fastest close passes. Hero feature moments must land sharp and readable.
- No human, hand, laptop, room, phone mockup, generic AI brain, robot, particles, neon, lens flare, or unnecessary decorative environment.

## Assembly and continuity

1. Put all four clips in Flow Scenebuilder.
2. Use the last stable frame of each clip as the next clip’s first frame if it differs from the prepared anchor.
3. Cut on movement, not after movement stops. Ideally the camera is still carrying a small forward drift at each 8-second seam.
4. Use one continuous sound bed across all clips so the four generations feel like a single shot.
5. Reject takes with weak camera travel even if the UI is clean. The ad’s idea is the journey.
6. Reject takes where the camera spins, text floats loose, UI bends, or the product becomes holographic.

The most important selection test: watch the clip muted and squint. You should still feel a clear path—**enter, accelerate, pass close, reveal, land**—in every eight-second section.
